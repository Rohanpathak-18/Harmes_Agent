HERMES - WEBSITE USER GUIDE01
01 - GETTING STARTED

Open your workspace

Hermes is a workspace for coordinating content jobs. A job holds the objective and progress for one piece of work. Your account keeps the workspace private to your sign-in.

Before using the website

Services must be available

The website needs its API server and database. Job processing also needs Redis and a running worker. If the app is run locally, keep those services running while using Hermes.

Use the website address

Open the local or deployed website address provided for your workspace. The code project's development website commonly runs at http://localhost:5173; the API server is separate.

HERMES - WEBSITE USER GUIDE02
LOCAL SETUP

Start a local workspace

If you use a hosted workspace, skip this page. To run the local project, start its supporting services and leave them running while you use the website.

1 - Start Redis

Open Docker Desktop and wait for its engine to be ready. In PowerShell, start the existing container:

docker start hermes-redis docker exec hermes-redis redis-cli ping

The second command should return PONG. If the container has never been created, run this once instead:

docker run --name hermes-redis -p 6379:6379 -d redis:7-alpine

2 - Start the API and job worker

In two separate PowerShell windows from the project folder:

cd server; npm run dev cd server; npm run worker

The server needs a working database connection configured for the project.

3 - Start the website

In another PowerShell window from the project folder:

cd client; npm run dev

Open the local address shown by Vite, commonly http://localhost:5173.

Publishing jobs

When using local publishing, start the publisher worker in another server terminal with cd server; npm run publish-worker. Actual publishing also depends on the configured platform integration.

HERMES - WEBSITE USER GUIDE03
01 - GETTING STARTED

Access your workspace

Create an account

1

On the sign-in screen, choose Create one to open registration.

2

Enter your name, workspace name, work email, and a password of at least eight characters. Confirm the password and submit.

3

Check your email for the six-digit verification code. Enter it on the verification page. The code expires after ten minutes; use Resend code if needed.

4

After verification, Hermes opens the Dashboard. On later visits, sign in with your email and password.

Forgot your password?

Choose Forgot password? on sign-in, request a reset code by email, then enter that code and a new password on the reset screen.

Know the navigation

The left menu is the main workspace map: Overview, Jobs, Create, Research, Content, Production, Approval, Publishing, Analytics, Learning, and Settings. On smaller screens, open the menu using the navigation control.

HERMES - WEBSITE USER GUIDE04
02 - YOUR FIRST JOB

Create a clear objective

A job tells Hermes what outcome you want. It is the starting point for the workflow and the place to return to check status.

1

From the Dashboard, select Create job. You can also choose Create in the left menu or New job on the Jobs page.

2

Write a specific objective in the text box. State the subject, intended audience, format, and desired outcome. The objective must be at least ten characters.

Example of a useful objective

"Research three current AI productivity trends for small businesses and develop a concise YouTube explainer for founders, including a clear practical takeaway."

3

Select a priority: Low to process when capacity allows, Normal for standard work, or High to prioritize the job.

4

Choose Create job. Hermes saves the job and opens its details page. If you change your mind before submitting, choose Cancel.

What you'll see on the Dashboard

The Dashboard summarizes total jobs, active jobs, jobs waiting for approval, and completed jobs. Recent Jobs gives quick access to individual work; Activity summarizes job status. Select a count or job to jump to its workspace.

Good objectives make better jobs

Describe the result you need rather than how the software should do it. Avoid secrets or sensitive personal information in job descriptions.

Find an existing job

Open Jobs, search by words in the objective, and optionally filter by status. Use Refresh to fetch current job data. Select a job card to view its details and progress.

HERMES - WEBSITE USER GUIDE03
03 - RUN & TRACK

Start and follow the workflow

Creating a job saves it. To begin processing, open the job and explicitly choose Run workflow. A background worker then carries out the workflow stages.

1

On the job details page, confirm the objective and priority.

2

For a new job marked Discovered, choose Run workflow. Keep the API, Redis, and worker services available while it runs.

3

Watch the status and workflow timeline. Choose Refresh if the page has not updated. You can return to the job later from Jobs or the Dashboard.

Discovered >Researching >Research ready >Scripting >Production >Final QA >Waiting approval

What each status means

DiscoveredCreated and ready to start. ResearchingResearch is being prepared. Research readyResearch stage completed. ScriptingPlanning and writing are in progress.

ProductionProduction assets are being prepared. Final QAQuality checks are running. Waiting approvalHuman review is required before publishing.

ApprovedReview passed. ScheduledAdded to the publishing queue. PublishedPublication is recorded. Analyzing / LearnedPerformance is being turned into insights. FailedA processing step needs attention.

Use the stage pages

Research, Content, Scripts, and Production show which jobs have reached those stages and link to each job. They are progress views; the current website does not provide separate editing workspaces there. Open the job to see its objective, timeline, status, and any recorded error.

If a job fails

Open its details page and read Last error. Confirm services and required integrations are available. If the underlying issue is resolved, choose Retry job to enqueue another attempt, then monitor the job again.

HERMES - WEBSITE USER GUIDE04
04 - REVIEW CONTENT

Review before publishing

Hermes runs quality checks before a job reaches approval. A person still makes the approval decision; a job is not meant to publish itself without that review.

Open the Approval center

1

Choose Approval in the left menu. Jobs at or beyond final QA appear in the list.

2

Read the objective and status. Choose View to open the full job details and timeline before deciding.

3

If an approval request has not been created yet, choose Request approval. Jobs that reached approval through the workflow may already have a pending request.

4

For a pending request, choose Approve to allow the job to continue, or Reject and enter a reason. Rejected jobs return to the final QA state for follow-up.

Approve when ready

Approval changes the job to Approved. It becomes eligible to enter the publishing queue.

Reject with a reason

Give a short, actionable explanation so the issue is clear. Rejection does not publish the job.

Important review boundary

The current interface is focused on job status, objective, and timeline. It does not expose a full in-app script or media editor on the Research, Content, Scripts, or Production pages. Review the actual deliverable through the available job or asset records and your team's review process before approving.

Make approval deliberate

Check accuracy, rights to use any material, brand fit, and the intended destination using your normal editorial standards. Use the job's recorded information as workflow context, not as a substitute for reviewing the finished deliverable.

HERMES - WEBSITE USER GUIDE05
05 - PUBLISHING

Queue approved work

Once approved, a job can be added to the publishing pipeline. The queue is separate from the approval decision, so the user controls when approved work is queued.

1

Choose Publishing in the left menu. Approved, scheduled, and published jobs are shown here.

2

Review the job details and its approval status. Choose View to return to the job if you need more context.

3

For an approved job that is not already scheduled or published, choose Queue. Hermes records it in the publishing queue and marks it scheduled.

4

Use Refresh to see updates. For a completed publication with a URL, choose Open to visit it.

Publishing depends on setup

Queuing work records the publishing request. Actual delivery and the availability of a public destination depend on the publishing worker, platform credentials, and integration configuration for the environment.

When something is missing

  • If a job does not appear, refresh and confirm it has been approved.
  • If Queue reports an error, check the job's status and the publishing service/worker configuration.
  • If no Open link appears, the publication record may not yet contain a destination URL.

Statuses to expect

Approved means eligible to queue. Scheduled means it is in the queue. Published means publication has been recorded. The Publishing page displays a URL only when one is available.

HERMES - WEBSITE USER GUIDE06
06 - MEASURE & IMPROVE

Use Analytics and Learning

These areas help you review available performance information after content has been published. What appears depends on whether analytics records exist for the job.

Analytics

Open Analytics to see the available totals, such as views, likes, comments, and retention. Choose Refresh to reload the records. Empty metrics usually mean no analytics snapshot has been recorded yet.

Learning

Open Learning to review insights and recommendations derived from available performance data. A confidence value may appear when the insight has one.

Generate an insight

1

Open Learning and find a job that is published, analyzing, or learned.

2

Choose Analyze [job] in the Generate new insights section.

3

After the confirmation appears, review the insight and any recommendation in the Insights list.

Insights depend on input data

Analytics and learning are only as complete as the available performance records. If a published job has no data yet, return later or confirm that performance data has been captured for it.

Return to your workspace safely

Open Settings to review your name, email, and verification state. Choose Sign out when you finish; this ends the current session.

Use the Dashboard and Jobs list as your starting point when returning to ongoing work. Search by objective or filter by status, then open the relevant job.

Good team habits

  • Write one clear objective for each distinct content operation.
  • Use the job status as the shared indication of progress.
  • Keep approval decisions and rejection reasons tied to the correct job.
  • Confirm publication and analytics availability before drawing conclusions from performance.
HERMES - WEBSITE USER GUIDE07
07 - QUICK TROUBLESHOOTING

When the website doesn't respond

Many issues are caused by a dependency being unavailable or a job not yet reaching the required status. Use this checklist to find the right next step.

Sign-in or verification does not work

Confirm you used the correct email and password. Check Spam/Promotions for the six-digit code, verify that it has not expired, and use resend when available. Password reset starts from the sign-in page.

Dashboard or Jobs cannot load

Refresh the page. If the API is unavailable, wait for the server to recover or contact the workspace administrator. Confirm the browser can reach the configured website and API.

Redis shows ECONNREFUSED at 127.0.0.1:6379

For a local setup, start the existing Redis container with docker start hermes-redis. Check it with docker exec hermes-redis redis-cli ping; a healthy response is PONG. Then restart the server and make sure the job worker is running. If Docker says its engine is unavailable, start Docker Desktop first.

Run workflow does not advance

Confirm Redis and the job worker are running, then refresh the job. Read Last error if status is Failed. After resolving the stated issue, choose Retry job.

Approval or Queue action fails

Confirm the job is at the correct status and refresh. Approval requires a pending request; publishing requires approval and a suitable publishing setup.

Analytics or Learning is empty

Confirm the job has publication/performance records. Refresh or revisit after data has been recorded.

When asking for help

Share the page name, job status, the visible error message, and the action you took. Do not share passwords, verification codes, API keys, or session cookies.

HERMES - WEBSITE USER GUIDE08
PROJECT OVERVIEW - FINAL PAGE

What Hermes is

Hermes is a content operations workspace that organizes a content idea into a trackable job, coordinates automated work, keeps human approval in the process, and provides a place to review publication and performance information.

Idea >Research >Plan & script >Production >Quality check >Human approval >Publishing queue >Learning

How it works for a user

1 - Organize

Create a job with an objective and priority. The Dashboard and Jobs list make work easy to find and monitor.

2 - Process

Start the job workflow. Hermes uses its configured services and agents to carry work through research, content development, production, and quality checks.

3 - Govern

Review jobs in Approval. Human approval is a distinct step before an approved job can enter the publishing queue.

4 - Improve

Review available performance records and generate learning insights that can inform future content decisions.

What the current website includes

Account registration and verification; Dashboard and job management; job creation, status tracking, and retry; stage views for Research, Content, Scripts, and Production; approval and rejection; publishing queue controls; analytics and learning views; and account/session settings.

What determines the experience

Available actions and results depend on job status and on the services and integrations configured for the environment. In the current website, the stage pages are tracking views rather than full editing canvases. Publication links and performance insights appear when corresponding records are available.

The purpose

Give a team one clear place to move content work forward, see where each job stands, keep a person responsible for approval, and learn from results.
